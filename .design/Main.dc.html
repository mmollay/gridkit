GridKit 1.27.3 Design-Audit · 26. August 2026

Das Token-System ist fertig gebaut.
Die Komponenten benutzen es nicht.

GridKit hat eine saubere M3-Farbrollen-Schicht — --gk-primary, Surface-Container-Stufen, sechs Themes, Dark Mode. Diese Schicht funktioniert. Darunter liegen aber 482 fest verdrahtete Hex-Werte, die sie überstimmen. Das Ergebnis ist im Browser messbar: im Light Mode sehen alle sechs Themes identisch aus, und im Dark Mode ist jede zweite Tabellenzeile unlesbar.

Kritisch 0/9 Komponenten reagieren auf den Theme‑Wechsel Gemessen: Theme auf forest gesetzt, --gk-primary wird #059669 — Button bleibt indigo.
Kritisch 1,16:1 Kontrast der Zebra‑Zeilen im Dark Mode WCAG AA verlangt 4,5:1. Der Text ist praktisch unsichtbar — jede zweite Zeile.
Ursache 482 fest verdrahtete Hex‑Werte in gridkit.css Dem stehen 455 var(--gk-…) gegenüber. Über die Hälfte der Farbentscheidungen umgeht das System.
Ursache 16 verschiedene Schriftgrößen, keine Skala 10, 11, 12, 13, 14, 15, 16, 17, 18, 20, 22, 24, 28, 32, 36, 56 px — als Literale verstreut.

Der Kern-Befund in vier Zeilen

Heute · gridkit.css Zeile 877
.gk-btn-filled.gk-btn-primary { background: #6366f1; color: #fff; border-color: #6366f1; }
Der Wert ist eine Kopie von --gk-primary — aber eben eine Kopie. Theme-Wechsel erreichen sie nie.
Veredelt · eine Regel für alle sechs Themes
.gk-btn-filled.gk-btn-primary { background: var(--gk-primary); color: var(--gk-on-primary); border-color: var(--gk-primary); }
Dieselbe Regel gilt dann auch im Dark Mode. Die 73 Dark-Mode-Patches darunter werden überflüssig.

Das ist die gute Nachricht dieses Audits: Es fehlt kein Konzept. Das Konzept steht und ist gut — es wird nur an rund 480 Stellen nicht angewendet. Der teuerste Teil einer Design-System-Sanierung, die Entscheidung, was die Tokens sein sollen, ist hier bereits getan.
